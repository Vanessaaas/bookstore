# BookStore

Информационная система книжного магазина: каталог с цветовой подсказкой статусов, роли сотрудников, реестр заказов с контролем просрочки.

Стек: Python 3.11+, FastAPI, SQLAlchemy 2 (ORM), PostgreSQL 14+, фронтенд на чистых HTML/CSS/JS.

## Состав проекта

| Путь | Что внутри |
|------|------------|
| `database/create_db.sql` | Скрипт создания БД: таблицы, ключи, ограничения, индексы и данные из выгрузок |
| `docs/er_diagram.pdf` | ER-диаграмма (нотация «вороньи лапки») |
| `docs/login_flowchart.pdf` | Блок-схема алгоритма авторизации по ГОСТ 19.701-90 |
| `app/` | Backend на FastAPI: `models.py` (ORM), `routers/` (API), `security.py` (пароли и токены) |
| `app/static/` | Страницы: вход, каталог, форма книги, реестр заказов |
| `resources/images/` | Обложки книг. Сюда же сервер копирует загруженные администратором файлы |
| `tools/import/` | Исходные выгрузки старой системы (xlsx) |
| `tools/build_sql.py` | Пересобирает `create_db.sql` из выгрузок |
| `tools/init_db.py` | Создаёт базу и выполняет скрипт без psql |
| `tools/draw_er.py`, `tools/draw_flowchart.py` | Генерируют PDF-схемы |

## Запуск

1. Установите PostgreSQL (пользователь `postgres`) и Python 3.11 или новее.
2. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

3. Укажите строку подключения, если пароль postgres отличается от `postgres`:

   ```powershell
   $env:DATABASE_URL = "postgresql+psycopg2://postgres:ВАШ_ПАРОЛЬ@localhost:5432/bookstore"
   ```

4. Создайте базу и загрузите данные. Любой из двух вариантов:

   ```bash
   python tools/init_db.py
   ```

   ```bash
   createdb -U postgres bookstore
   psql -U postgres -d bookstore -f database/create_db.sql
   ```

5. Запустите сервер и откройте http://localhost:8000:

   ```bash
   uvicorn app.main:app --reload
   ```

Документация API: http://localhost:8000/docs.

## Как реализованы требования ТЗ

**Структура БД (3НФ).** Автор, жанр, издатель, клиент, роль и статус заказа вынесены в справочники. Строку «BK001, 1, BK002, 1» из выгрузки заказов скрипт раскладывает в таблицу `order_items` с составным ключом `(order_id, book_id)`. Артикул остался уникальным полем книги, а первичный ключ `id` назначает СУБД.

**Каталог.** Карточка показывает обложку (или заглушку `picture.png`), название, автора, жанр, рейтинг, цену, дату издания и остаток.
- «Новинка»: книга издана меньше 30 дней назад. Название становится жирным и зелёным.
- «Неликвид»: книга издана больше 2 лет назад и на складе больше 5 штук. Карточка окрашивается в светло-красный.
- «E-book»: метка на карточке электронной книги.

Флаги вычисляет сервер в `app/routers/books.py` (функция `to_card`).

**Поиск и фильтры.** Поиск по названию и описанию срабатывает при вводе (задержка 200 мс), жанр, сортировка и чекбокс срабатывают сразу при изменении. Кнопки «Найти» нет.

**Форма книги.** Поле ID в форме отсутствует. Цена и количество проверяются трижды: атрибутом `min="0"` в форме, схемой Pydantic и `CHECK` в БД. Обложку больше 2 МБ сервер отклоняет, а картинку крупнее 400×400 px уменьшает и сохраняет в `resources/images` под уникальным именем. При замене обложки старый файл удаляется.

**Удаление книги.** Если книга есть хотя бы в одном заказе, сервер отвечает ошибкой 409 «Книгу нельзя удалить: она присутствует в заказах». Ограничение `ON DELETE RESTRICT` дублирует эту проверку в БД. В остальных случаях интерфейс просит подтвердить удаление.

**Заказы.** Строка заказа становится ярко-красной, если дата доставки прошла, а статус не финальный. Финальные статусы («Завершен», «Отменен») отмечены флагом `order_statuses.is_final`. Менеджер меняет статус и дату доставки прямо в строке и нажимает «Сохранить». Дату раньше даты оформления сервер не примет.

## Допущения

- В выгрузке роль продавца записана как «Продвавец». Скрипт импорта исправляет опечатку.
- Две даты издания в выгрузке записаны строкой («20.06.1890», «01.01.1869»). Скрипт их распознаёт.
- В исходных данных нет книг моложе 30 дней, поэтому метка «Новинка» появится после того, как администратор добавит книгу со свежей датой.
- «Только в наличии» скрывает книги с остатком 0, включая электронные.

## Проверочный запуск без PostgreSQL

Для быстрой проверки подойдёт SQLite: схему создаёт ORM, данные берутся из того же `create_db.sql`.

```powershell
$env:DATABASE_URL = "sqlite:///bookstore_test.db"; python tools/init_db.py; uvicorn app.main:app
```
